# Step 02: 인터페이스 포인트 자동 추출

## MANDATORY RULES (반드시 먼저 읽기):

- 📖 이 파일을 끝까지 읽은 뒤에만 행동한다
- ⚡ PRD에서 자동 추출할 수 있는 것은 사용자에게 묻지 않는다
- 🔍 추출 시 누락이나 오분류보다 과포함이 낫다 — 사용자가 줄일 수 있다
- ✅ 추출 결과를 사용자가 검토·수정하도록 반드시 제시한다
- 💬 `{communication_language}`로 모든 출력을 작성한다

## 이 단계의 목표

PRD 전문을 분석하여 4종류의 인터페이스 포인트를 자동 추출하고, 사용자가 검토·확정한다.

---

## 실행 순서

### A. PRD 분석

PRD 전체를 분석하여 아래 4가지 범주의 인터페이스 포인트를 추출한다.

**추출 기준표:**

| 범주 | 탐지 신호 | 산출물 파일 |
|------|----------|------------|
| API 엔드포인트 | "~를 조회한다", "~를 생성한다", "CRUD", "REST", "API", 기능 요구사항의 데이터 흐름 | `01-api.yaml` |
| WebSocket 이벤트 | "실시간", "협업", "알림", "푸시", "구독", "이벤트" | `02-ws-events.ts` |
| DB 테이블 / 스키마 | 엔티티명, 데이터 모델, "저장", "기록", "이력" | `03-schema.sql` |
| 외부 어댑터 | 외부 시스템명, "연동", "인터페이스", "어댑터", "브리지" | `04-adapter-interfaces.ts` |

### B. 추출 결과 정리

각 범주별로 아래 형식으로 정리한다.

**API 엔드포인트 초안:**
```
[A-001] GET /articles/{id}              — 기사 단건 조회
[A-002] POST /articles                  — 기사 신규 생성
[A-003] PUT /articles/{id}              — 기사 전체 수정
[A-004] PATCH /articles/{id}/layout     — 레이아웃 부분 수정
[A-005] DELETE /articles/{id}           — 기사 삭제
...
```

**WebSocket 이벤트 초안:**
```
[W-001] article:lock              → 기사 편집 잠금 획득
[W-002] article:unlock            → 기사 편집 잠금 해제
[W-003] article:patch             → CRDT 패치 브로드캐스트
[W-004] cursor:move               → 공동 편집자 커서 위치
[W-005] presence:join / :leave    → 편집자 입장/퇴장
...
```

**DB 테이블 초안:**
```
[D-001] articles          — 기사 메타데이터
[D-002] article_versions  — 버전 이력
[D-003] users             — 사용자 계정
[D-004] sessions          — 편집 세션
[D-005] media_assets      — 이미지/미디어
...
```

**외부 어댑터 초안:**
```
[X-001] NedAdapter        — NED 뉴스 공급 시스템 연동
[X-002] AviAdapter        — AVI 사진 시스템 연동
[X-003] PrintServerAdapter — 인쇄 서버 명령 전달
[X-004] SsoAdapter        — 사내 SSO 인증 브리지
[X-005] KisaAdapter       — KISA 보안 정책 적용
...
```

### D. 사용자 수정 반영

사용자가 수정 요청을 하면:
- 해당 항목을 즉시 수정·추가·삭제한다
- 수정된 전체 목록을 다시 보여준다
- [C] 메뉴를 다시 제시한다

수정 없이 [C]를 선택하면 다음 단계로 진행한다.

---

## 추출 결과 저장

사용자가 [C]를 선택하면 추출된 인터페이스 포인트 목록을 메모리에 유지한다.  
이 데이터는 Step 03~06에서 계속 참조한다.

---

## SUCCESS CRITERIA:

✅ 4가지 범주 모두 추출 시도  
✅ 추출 결과를 ID 포함하여 사용자에게 제시  
✅ 사용자 수정 반영  
✅ 사용자 확정 후에만 다음 단계 진행  
✅ 과소 추출보다 과포함 후 사용자 정리를 허용  

## FAILURE MODES:

❌ 추출 없이 사용자에게 목록 작성 요청  
❌ 일부 범주 누락 (4가지 모두 시도해야 함)  
❌ 사용자 확인 없이 다음 단계 진행  
❌ ID 없이 목록만 제시
