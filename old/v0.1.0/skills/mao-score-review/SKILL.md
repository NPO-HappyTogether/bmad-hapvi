## 점수 가중치 (기본값)

| 항목 | 가중치 | 설명 |
|------|--------|------|
| 계약 준수 | 40% | 계약서 인터페이스 타입·시그니처 일치 |
| PRD 커버리지 | 30% | PRD AC 항목 구현 비율 |
| 연동 준비도 | 20% | 타 에이전트 인터페이스 호환성 |

## 활성화 시

설정 로드 후 즉시 평가 시작. 단독 실행 시 평가할 에이전트 목록 확인.

## 평가 워크플로우

### LEVEL 1 — 자동 평가 (완전 자동, 사람 개입 없음)

각 에이전트에 대해 병렬 실행:

**A. 계약 준수 (40%)**
- 에이전트 계약서에서 인터페이스 정의 추출 (타입, 시그니처, 엔드포인트, 이벤트)
- 결과물 파일에서 실제 구현 추출
- 항목별 점수: 일치=1.0 / 부분일치=0.5 / 불일치=0.0
- 점수 = (합계 / 전체 항목) × 10

**B. PRD 커버리지 (30%)**
- PRD에서 해당 에이전트 도메인 AC 추출
- 결과물에서 구현 증거 탐색 (키워드, 파일 존재, export)
- 점수 = (증거 있는 AC / 전체 AC) × 10

**C. 연동 준비도 (20%)**
- 타 에이전트 계약서에서 이 에이전트가 제공해야 할 인터페이스 목록 추출
- 결과물에서 export/공개 여부 확인
- 모두 공개=10 / 절반 이상=6 / 절반 미만=3 / 전무=0

**D. 코드 품질 (10%)**
- `@ts-ignore` 사용 수, `any` 남용, 미구현 stub(TODO/throw) 탐색
- 0개=10 / 1~2개=7 / 3~5개=4 / 6개 이상=0

**E. 가중 평균 계산**
`종합점수 = (계약준수×0.4) + (PRD커버×0.3) + (연동준비×0.2) + (코드품질×0.1)`

**F. 레벨 분류**
- 8~10점: PASS
- 6~7점: LEVEL_2 (요약 검토)
- 0~5점: LEVEL_3 (상세 검토)

---

### LEVEL 2 — 요약 검토 (6~7점 에이전트만)

LEVEL_2 에이전트의 `README.md`, `index.ts`, `package.json`만 읽기.
문제 항목 목록 생성: `{ 파일명, 이유 }`.

---

### LEVEL 3 — 상세 검토 (0~5점 에이전트만)

불일치 계약 항목과 연결된 파일만 타깃으로 읽기 (전체 소스 금지).

각 불일치 항목에 대해:
- 정확한 파일 경로 및 줄 범위
- 무엇이 잘못됐는지 (계약 기대값 vs 실제값)
- 왜 틀렸는지
- 어떻게 수정할지
- 어떻게 검증할지

### 점수판 생성 및 출력

`{scoreboards-root}round-{round}-scoreboard.md` 저장.

```
📊 점수판 — 라운드 {round}
평가 기준: 계약준수 40% | PRD커버 30% | 연동준비 20% | 코드품질 10%

| 에이전트 | 계약준수 | PRD커버 | 연동준비 | 코드품질 | 종합 | 상태 | 필요 조치 |
|---------|---------|---------|---------|---------|------|------|---------|
| ...     |         |         |         |         |      | ✅/⚠️/❌ |       |

✅ PASS (8~10): 통과
⚠️ LEVEL_2 (6~7): 요약 재브리핑 필요
❌ LEVEL_3 (0~5): 정밀 재브리핑 필요
```

**mao-orchestrate에서 호출된 경우:** 점수 데이터 구조 반환 후 제어 이양.
**단독 실행인 경우:** 사용자에게 다음 4가지 선택지 제시:
1. 모두 통과 → 다음 단계 진행
2. 재브리핑 → mao-orchestrate로 이동
3. 수동 개입 → 특정 에이전트 ID 지정
4. 평가 기준 조정 → 가중치 변경 후 재평가
