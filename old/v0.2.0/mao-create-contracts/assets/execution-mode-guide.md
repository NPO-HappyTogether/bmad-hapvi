# 실행 모드 가이드

이 가이드는 `mao-create-contracts` 스킬의 **실행 모드** 선택 기준과
각 모드에서 생성되는 계약서 상세도를 설명한다.

---

## 세 가지 실행 모드

### T — 타이트 (Tight)

**원칙:** 에이전트 자율 최소화. 모든 인터페이스를 완전히 명시한다.

**적합한 상황:**
- 여러 팀이 동일 API를 병렬로 개발할 때
- 외부 파트너나 고객에게 공개되는 API가 있을 때
- 규정 준수(ISMS, GDPR 등)가 필요한 인터페이스가 있을 때
- 에이전트 구현 결과의 일관성이 최우선일 때

**각 파일별 생성 수준:**

| 파일 | 타이트 수준 내용 |
|------|----------------|
| `01-api.yaml` | 모든 필드명, 타입, required, enum, 에러코드, 예시값 완전 명시 |
| `02-ws-events.ts` | 이벤트별 페이로드 타입 완전 정의, 에러 타입, 재시도 정책 |
| `03-schema.sql` | 컬럼 타입, NOT NULL, DEFAULT, CHECK, INDEX, FK, COMMENT 모두 포함 |
| `04-adapter-interfaces.ts` | 메서드 시그니처, 파라미터 타입, throws, 타임아웃 옵션 완전 정의 |

---

### R — 러프 (Rough)

**원칙:** 에이전트 자율 최대화. 목적과 형태만 명시하고 구현은 에이전트에게 맡긴다.

**적합한 상황:**
- 단일 팀이 전체 스택을 개발할 때
- 초기 탐색 단계로 인터페이스가 자주 바뀔 때
- 에이전트의 창의적 판단을 신뢰하고 싶을 때

**각 파일별 생성 수준:**

| 파일 | 러프 수준 내용 |
|------|--------------|
| `01-api.yaml` | HTTP 메서드, 경로, 목적 설명만. 스키마는 `# TODO` 주석 |
| `02-ws-events.ts` | 이벤트명, 방향(C→S/S→C)만. `payload: unknown // TODO` |
| `03-schema.sql` | 테이블명, 핵심 컬럼만. 인덱스는 `-- TODO` 주석 |
| `04-adapter-interfaces.ts` | 인터페이스 이름, 핵심 메서드 시그니처만. 타입은 `any // TODO` |

---

### M — 혼합 (Mixed) ★ 권장

**원칙:** 인터페이스 경계(팀 간 계약)는 타이트하게, 내부 구현은 에이전트 자율.

**적합한 상황:**
- 대부분의 프로젝트
- 외부 시스템 연동은 엄격하게, 내부 로직은 유연하게 하고 싶을 때

**레이블 기본 규칙 (Step 04에서 항목별 조정 가능):**

| 항목 유형 | 기본 레이블 | 이유 |
|----------|------------|------|
| 외부 공개 API | TIGHT | 클라이언트 앱이 의존 |
| 내부 API (서비스 간) | MIXED | 팀 간 계약은 명확히, 내부 처리는 자율 |
| WebSocket 이벤트 | ROUGH | 실시간 특성상 유연성 필요 |
| 핵심 DB 테이블 | TIGHT | 데이터 무결성 보장 |
| 임시/캐시 테이블 | ROUGH | 구현 세부사항 |
| 외부 어댑터 인터페이스 | TIGHT | 외부 시스템 계약 |
| 내부 유틸리티 | ROUGH | 구현 자율 |

---

## 모드별 TODO 주석 규칙

러프 처리 항목에는 다음 주석을 사용한다:

**YAML:**
```yaml
# TODO(mao-rough): 에이전트가 컨텍스트에 맞게 정의
# 참고: {관련 결정 또는 PRD 섹션}
```

**TypeScript:**
```typescript
// TODO(mao-rough): 에이전트가 컨텍스트에 맞게 구체화
// 참고: {관련 결정 또는 PRD 섹션}
```

**SQL:**
```sql
-- TODO(mao-rough): 에이전트가 컨텍스트에 맞게 확정
-- 참고: {관련 결정 또는 PRD 섹션}
```

에이전트는 TODO를 구현한 뒤 `.decision-log.md`의 에이전트 위임 항목 표에 선택 이유를 기록한다.
